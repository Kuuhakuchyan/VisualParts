# 微境探界大屏与竞赛版联动验收

## 产品结构

- 主平台 /decision/ 和竞赛版 /decision/aic/ 均以可视化大屏为默认入口。项目名称均为“微境探界”，不是两个不同项目。
- 大屏保留全幅地图、天气与小时趋势、环境风险、数据链路和图层控制。五个操作工作台用于详细维护，不替代大屏。
- 大屏可直接选点，打开侧边面板完成方案保存、比较、导出、打印和确认删除，也可进行热风险评估与来源核查。关闭面板后回到原地图，不重新创建场景。
- 竞赛版复用同一套页面代码、地图引擎与功能，隐藏平台管理与项目主页链接；独立保存匿名工作区凭证，避免自动带入主平台旧方案。地域与气象位置保留，不能将匿名理解为删除数据地理信息。
- 继续保留既有项目标志；本轮不编造或替换成员与指导教师信息。竞赛版不展示人员身份。

## 三维与数据边界

- 使用 Three.js 与 MapLibre 共享 WebGL 场景；沿现有160栋OSM建筑轮廓挤出，改善顶面/侧面材质、轮廓线、定向光照和选中高亮，提供影像/街道底图、平面/倾斜、环绕与回位。
- 建筑仍是基于现有轮廓的示意模型，不是精细实景重建或实测模型。高度缺失按18米示意；光照滑块只控制展示方向，不是实时太阳、阴影面积或辐射计算。
- 不增加假窗户、虚构纹理、随机热场、在线设备或温降结果。Three.js失效时保留基础建筑体块；地图失败时仍保留天气、表单和证据操作。
- Three.js和地图按需加载，环绕不自动播放，拖动或打开操作面板时停止，后台标签页暂停。默认不保留绘图缓冲区；仅 capture=1 验收时启用像素读取。

## 部署与科学门禁

本轮仅部署静态前端，不替换后端、数据库、密钥或医师审核记录。上线前备份整个静态目录，保留旧哈希资源与数据目录，覆盖构建产物后再回查公网两版。
