# V1.0 工程收口

本批基于 `platform-decision-integration` 整理。2026-11-15 检查远端时，`weather-platform` 是当前分支的祖先，当前分支领先 22 次提交。不要直接用旧分支覆盖现有功能，也不要将其他分支的修改无差别合并到部署目录。

## 软件身份与发布身份

- 软件名称和版本以 `decision/release-version.json` 为准，目前为 `1.0.0` 候选版。
- API 默认版本读取该文件；显式设置的 `APP_VERSION` 继续作为部署标识，兼容已有部署脚本。
- `/health` 的 `softwareVersion` 是软件版本，`version` 是当前部署标识。
- 每次前端构建生成 `dist/build-manifest.json`，包含软件版本、Git 提交号、工作区是否存在修改、构建时间以及每个产物的 SHA-256。
- 没有 Git 信息时标记 `null`，工作区仍有未提交内容时标记 `source_dirty=true`，不能把它当成最终冻结版。
- `build-manifest.json` 只用于交付核对，不替代业务结果的 `snapshot_sha256`、规则版本或报告哈希。计算链条不改用软件版本来判断结果相同。

## 运行资源

`runtime-assets.json` 列出需要随 API 交付的空间数据、模型、知识库和版本文件。Docker 构建复制公共空间资源及 JSON 模型，并执行 `python -m backend.release_check`。资源缺失、JSON 损坏或清单路径越界时构建失败。

本批也修正了道路、街区和 LCZ 约束资源被 Git 忽略的问题。解除忽略不等于这些文件已经提交，仍需在候选版快照中逐项核对。

原始观测、设备图像、SQLite 状态、生产 `.env`、模型 API 密钥、医学审核私有材料不属于公共静态资源，不纳入提交包。模拟热场和模拟采集可以用于功能演示，真实数据是否公开由团队决定。

## 本地回归

在 `decision/` 下，使用 Python 3.12 和 Node.js 22.12 以上版本：

```powershell
python -m pip install --require-hashes -r requirements-test.lock
npm ci
python scripts/verify-release.py --report-dir output/release-check
```

脚本依次执行资源检查、后端测试、设备平台安全测试、临时目录包启动测试、工作区与预报/主页几何测试、本地资源路由测试和生产构建，任一步失败即停止。结果写入 `summary.json` 与各步骤日志。业务状态使用临时数据库，不连接线上状态目录；测试环境清除模型密钥及医学审核配置。

临时目录测试分别启动项目版和竞赛版 API，检查建筑模型、LCZ、路网、时序模型与空间代理模型可读取，同时验证竞赛版没有真实遥测路由。该检查使用当前 Python 环境，**不等同于完整 Docker 镜像验证**。

本机 Docker daemon 未启动时不改动生产 Docker；GitHub PR/手动工作流另执行 Linux Docker 构建及镜像内资源检查。只有工作流实际执行成功，才记录为 Linux 镜像通过。

## 源代码盘点

```powershell
python scripts/audit-release-source.py --report output/source-inventory.json
```

该命令只生成文件分类、跟踪状态和内容哈希；凭据模式命中只报告文件、行号和规则，不输出密钥值。不自动提交、不删除文件，也不上传数据。模式检查不能证明不存在所有类型的密钥，提交前仍需检查配置与开发脚本。

## 后续验收顺序

1. 从候选提交导出干净源代码，重新安装依赖，运行上述回归并核对必需文件全在 Git 中。
2. 回归天气到人群研判、拆建到重算保存回读、UGV/UAV 到设备树、逐小时热场到报告四条业务链。
3. 验证 Edge、桌面与手机操作，再做超时、重复点击、并发保存、异常输入与备份恢复演练。
4. 冻结源代码和界面后，导出真实截图、用户手册与源代码鉴别材料；资料格式以申报时受理系统要求为准。

以上为交付收口流程，不要求公开真实设备数据，也不要求先完成未来研究路线。模拟数据需要保持可重复、可替换和结果版本一致。
