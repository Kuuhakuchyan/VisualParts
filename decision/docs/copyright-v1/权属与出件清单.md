# 权属与出件清单

## 团队核定的事实

| 事项 | 核定依据 |
|---|---|
| 著作权人和申请主体 | 项目协议、任职/在校成果约定、合作或委托开发协议等；不由网页署名直接推定 |
| 开发方式 | 按实际独立、合作、委托或任务开发情况填写 |
| 完成日期 | 以具体申报版本的开发及验收记录核定，不沿用旧模板日期 |
| 首次发表日期与状态 | 网站已公开，需核实具体版本首次公开情况，不能直接填写“未发表” |
| 软件名称与版本 | 与冻结代码、界面、申请表、手册和源代码页眉一致 |

## 源代码和第三方边界

- 第一方代码从冻结候选提交导出；记录提交号、文件清单和 SHA-256。
- 不从历史 `manual_source_*` 等模板凑代码页数，不把 `node_modules`、框架代码或压缩依赖计入团队原创。
- MapLibre GL JS、Apache ECharts、Cesium、Three.js、字体、Python 科学计算组件等按实际依赖保留各自 LICENSE/NOTICE；与已有许可包核对版本。
- 团队制作的道路、建筑等空间数据保留原工程、制作记录及所依底图来源；OSM 相关衍生数据保留来源和适用许可说明。
- 第三方地图服务、图像和专业知识来源与第一方软件分开记录，不以软件登记代替第三方授权。

## 数据保密

提交包使用模拟或脱敏样例，可复现主要功能即可。生产数据库、真实轨迹、原始设备图像、私有属性和密钥不随公共演示包分发。使用模拟数据不会阻碍接口支持真实数据，但应通过相同字段契约验证接入流程。

## 工程出件

1. 候选源代码快照与版本清单。
2. 干净目录回归结果、构建清单及部署说明。
3. 最终名称与事实信息核定后的申请信息。
4. 与该版本一致的用途说明、操作手册和真实界面截图。
5. 按受理要求整理的第一方源代码鉴别材料。
6. 依赖许可、数据来源及需要保留的团队权属文件。

本目录中的工程审计、失败日志和内部待办用于团队准备，不自动作为申请附件提交。正式材料的页数、格式及提交方式在出件时按受理平台当前要求核对。
