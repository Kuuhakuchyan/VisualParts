# 运行维护与备份恢复

## 数据范围

四类 SQLite 状态分别为 `DECISION_STATE_DB`、`WORKSPACE_STATE_DB`、`AIC_STATE_DB`、`TELEMETRY_STATE_DB`；遥测图片目录为 `TELEMETRY_MEDIA_DIR`。项目版与竞赛版若使用不同路径，应分别备份。固定传感器记录、位置与字段定义等位于 PostgreSQL，不包含在 SQLite 备份中。静态资源、模型、知识条款和许可文件由 Git 源码及发行清单管理。

备份可能包含内部数据，应放在受限目录并另行复制到受控介质。不要上传公开仓库或放入软著提交附件。文件校验用于发现损坏；未加签的清单不提供抵御恶意重写整个备份的真实性保证。

## SQLite 与媒体

跨库、媒体的一致快照需要先停止相关写入者，包括应用 worker、设备接收和清理任务。工具不擅自停止服务，操作时由维护者确认停写窗口；单个 SQLite 文件使用数据库备份 API，避免直接遗漏 WAL 日志。

在 `decision/` 执行，路径替换为部署实际路径，输出目录必须尚不存在：

```sh
python -m backend.state_backup backup \
  --database decision=/state/decision.sqlite3 \
  --database workspace=/state/workspace.sqlite3 \
  --database evidence=/state/evidence.sqlite3 \
  --database telemetry=/state/telemetry.sqlite3 \
  --media /state/telemetry-media --output /backups/snapshot-001 --writers-stopped
python -m backend.state_backup verify /backups/snapshot-001
python -m backend.state_backup restore /backups/snapshot-001 --output /restore/recovery-001
```

恢复只写全新目录，拒绝覆盖已有目录、路径穿越、符号链接、缺失/多余文件及校验不匹配。校验包含 SQLite 完整性和各表记录数。恢复目录中的数据库在 `databases/`、媒体在 `media/`。恢复后先将隔离验收实例指向这些路径，验证方案、场景、原始观测、UGV/UAV 历史和图像的回读，再在维护窗口中切换生产配置；原目录保留用于回退。

模拟恢复演练：

```sh
python scripts/verify-state-recovery.py --output output/state-recovery
```

该流程创建真实应用表、模拟记录和模拟图片，逐表比较恢复前后的全部值，并从真实 API 回读；使用临时目录，不连接线上数据库。

## PostgreSQL

仓库根目录的 `scripts/backup_postgres.sh` 在指定容器内运行 `pg_dump --format=custom`，检查导出退出状态及 `pg_restore --list`，成功后才发布 `.dump` 文件。失败时清理临时文件，不发布空备份。旧 `.sql.gz` 不被新版清理规则删除。

生产备份示例（不要在日志中输出密码）：

```sh
BACKUP_DIR=/backups/postgres POSTGRES_CONTAINER=postgres_iot \
POSTGRES_DB=iot_platform POSTGRES_USER=iot_user sh scripts/backup_postgres.sh
```

恢复须使用与源库兼容的 PostgreSQL 主版本以及 PostGIS、TimescaleDB、pgvector 版本。先创建全新空数据库，安装 TimescaleDB，执行 `timescaledb_pre_restore()`；用 `pg_restore --exit-on-error --no-owner --no-privileges` 导入，随后执行 `timescaledb_post_restore()`。权限、属主和后台策略需按部署账号重新检查，不能直接覆盖生产库。

GitHub 的独立恢复任务从 `postgres.Dockerfile` 构建临时镜像，执行真实 `pg_init/001_init.sql`，用模拟设备、温湿度、空间位置和知识记录完成备份恢复，比较应用全部字段、扩展与两张超表，并验证失败导出不会误报成功。容器与测试库执行完自动清理。

## 同版浏览器验收

先构建当前源码，再启动仅监听本机的隔离模拟服务：

```sh
npm run build
python scripts/copyright-acceptance-server.py --state-dir output/copyright-state --port 18501
```

该服务复用实际页面和计算 API，只替换天气边界及设备输入；响应包含 `X-Test-Fixture` 和源码提交号，元信息位于 `/api/synthetic-provenance`。模拟的天气字段为接口兼容保留原类型，但名称和测试证据明确标为合成样例，不能当作公开接口实测或真实历史数据。页面入口为 `http://127.0.0.1:18501/decision/#screen`，设备页为 `/sensors`。

用 Playwright CLI 的 Edge 会话运行 `verify-construction-thermal-recompute.js`，可以验证拆建、改高、差值、撤销重做、手机布局和地图/报告/API逐格一致性；设备页运行 `verify-mobile-observation-ui.js`，验证有数据时的温湿度、轨迹、图像、搜索、刷新保留选项和故障时保留记录。实际手机触屏仿真另行记录，不以缩窄桌面窗口等同真机验收。
