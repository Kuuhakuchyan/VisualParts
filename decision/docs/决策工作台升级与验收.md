# 决策工作台升级与验收

## 定位与入口

更新说明：以下保留首轮工作台验收记录。后续已恢复可操作大屏作为默认入口，并将竞赛入口升级为同款大屏与子工作台；最新结构与验收见《大屏与竞赛版联动验收.md》。原风险表单位于 /decision/aic/assessment.html。

这是可追溯的环境与空间研判工作台，不是已完成物理标定的微气候预测系统。主入口为 `/decision/`，按需加载五个模块：态势总览、空间研判、热风险评估、方案对比、数据与依据。匿名竞赛页仍独立保留在 `/decision/aic/`，不加载学校、团队或导师信息。监测、传感器与日志页保留原有结构，同步统一配色并增加工作台、风险与依据的直接导航。

旧版页面移至 `/decision/legacy.html`，保留回溯用途，并显示常驻未验证演示提示。旧 What-If 和模拟报告默认返回409；只有明确设置 `DECISION_ENABLE_LEGACY_MOCK=1` 才能调试，不作为正式成果。新工作台不调用旧随机热风险、车辆或温降接口。

## 数据与方法

- 当前天气按中原区、校园周边分别取数，展示请求位置和实际模型网格。温湿度、风、降水检查范围与单位；错误辅助字段保留缺测。
- 小时资料保留过去24小时模型值、未来24小时预报的区分，缺测不插入随机值或连线填补。当前、历史与小时原始响应分别存档并生成SHA-256摘要。
- 每种资料与区域使用独立请求锁，避免慢速小时接口阻塞当前天气；当前120秒、小时300秒缓存。前端后台暂停轮询，路由切换销毁图表和地图。
- 空间页使用同源Esri影像和OSM建筑轮廓，建筑高度属性未现场核验，缺失按18米示意。天气点是模型网格中心，不是传感器位置。
- 支持图层显隐、平面/倾斜视角、建筑信息与地图选点，坐标可直接带入干预方案。当前不绘制未经验证的空间温度残差场。
- 遮阴方案仅算理想影长 `H/tan(太阳高度角)`，建筑体块另算面积乘高度，冷屋面记录反照率百分点变化，绿化只记录面积。太阳高度角为用户情景假设。
- 实际温降、通风、热暴露和置信度保持未验证，不用几何结果宣称环境改善，更不混合不同干预类型做伪排名。

## 方案与隐私

浏览器用256位随机凭证访问对应服务端SQLite工作区，只保存凭证哈希，不公开全局方案列表；每个工作区最多100个方案。凭证不进入方案导出。清空浏览器存储会失去原工作区访问能力，当前不是账号系统或跨设备同步。匿名症状报告不写入方案库。

支持跨模块保留未提交表单、检索档案、最多3项并列比较、逐项或对比JSON导出、打印及确认删除。输入与输出含规则版本和摘要，可重算但不等于数字签名。

医学知识、规则与AI调用继续受既有医师和来源版本门禁约束。现场采集、真实人工标注、专业审核、热环境模型标定与成果授权不能用软件测试替代。

## 部署与回退

1. 备份 `/root/microclimate-decision/backend`、服务drop-in、静态站和IoT API修改文件；SQLite由自身备份接口处理，不删除运行数据。
2. 后端采用 `/root/microclimate-decision/.venv`；设置 `WORKSPACE_STATE_DB=/root/microclimate-decision/aic_state/plans.sqlite3`。
3. 构建静态文件覆盖到 `/var/www/microclimate-decision`，保留 `data/` 与旧哈希资源，避免旧标签页失效。密钥、原始私密采集与审核文件绝不进入Web目录。
4. 后端重启后带重试检查health、两个区域天气、小时接口、风险紧急升级、凭证隔离及旧模拟409；再回读公开页面和移动端。
5. IoT API仅更新app.py与共享console.css，通过原compose的api服务重建，不重建或删除数据库及其他容器。
6. 失败时用本次备份恢复修改文件并重启对应服务；不回滚或清空观测/方案数据库。
